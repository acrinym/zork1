# Flathead Fair dialogue and contextual knowledge

**Status:** DESIGNING

## Core rule

No meaningless generic NPC response when the character reasonably knows something specific.

Dialogue should derive from:

- NPC identity and expertise;
- what they have seen/heard/tasted/been told;
- current location;
- time and fair state;
- mood;
- relationship history;
- prior conversation;
- object knowledge;
- current stock/job role.

## Correct ignorance

`I don't know; ask the drink seller` is valid when the character genuinely does not know. `I don't know anything about that` from the drink seller about their own drink is a design failure.

## Same object, different voices

An elephant ear can yield different useful answers from:

- its vendor: ingredients, preparation, price;
- Mara: preference, smell, prior memory;
- a child: size/excitement;
- an old regular: historical price/tradition;
- fair manager: location/concession information.

The knowledge may overlap; the voice and perspective should not.

## Repetition

Characters should not always replay first-contact prose when the player asks a known question again. Follow-up, impatience, jokes, or abbreviated answers are preferable where authored.

## Scope boundary

This is not an infinite chatbot layer. The fair supports a deliberately broad but bounded set of meaningful semantic questions tied to authored world facts.
